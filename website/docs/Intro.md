# Why Mailinator?

:::tip
Explore our product guides and [API documentation](/documentation/docs/api/) to learn how to test email, SMS, and authentication workflows with Mailinator.
:::

## Mailinator

Mailinator is an email, SMS, and authentication workflow testing platform for developers, QA teams, CI/CD pipelines, and AI agents. Whereas most email systems are built around the concept of "account/inbox ownership", Mailinator is built around "entire domain-inbox ownership". This allows teams to have instant access to millions of email addresses for system and automation testing of their software.

Learn more about [Private Mailbox](/documentation/docs/core/privatemailbox/).

Mailinator also provides a "public" domain for personal use where all email addresses (@mailinator.com) are completely public and usable by anyone. Public inboxes are useful for quick, non-sensitive testing, but Mailinator is not only a public disposable email service. Private domains, API access, SDKs, [webhooks](/documentation/docs/features/webhooks/), SMS, and [SSO/OIDC testing](/documentation/docs/features/universal-idp/) are designed for repeatable automation workflows.

Learn more about [Public Mailbox](/documentation/docs/core/publicmailbox/).

## Email, SMS, and Authentication Workflow Testing

Developers and testing teams can automatically test email, SMS, and authentication workflows like 2FA verifications, sign-ups, password resets, magic links, transactional notifications, and SSO login flows with trillions of inboxes at your fingertips.

Whether you test using an API tool like [Postman](/documentation/docs/test-automation/postman/), write code in a framework like [Cypress](/documentation/docs/test-automation/cypress/) or [Playwright](/documentation/docs/test-automation/playwright/), or connect an [AI agent](/documentation/docs/category/ai-agents/) through [CLI](/documentation/docs/ai-agents/mailinator-cli/) or [MCP](/documentation/docs/ai-agents/mailinator-mcp/) tooling, Mailinator closes the loop on workflow testing.
